## 2. Executer 抽象模型（需求 1：不止移除，还有修改/添加）

三层模型，声明与能力分离：

```
Intent(声明)   plans/*.json 中的 exec：资源类型 + 期望状态(ensure) + 参数（纯数据，绑定 arg 后不可变）
Provider(能力) IExecuter 实现：按资源类型 Inspect(读当前态) / Apply(收敛到期望态)
Tool(工具)     ProcessRunner → dism.exe / reg.exe / pwsh cmdlet / diskpart / robocopy
```

**核心理念（DSC 式收敛）**：增、改、删统一为同一资源的目标状态——
`ensure: absent` = 移除（卸功能、删文件、去预装应用）；`ensure: present` = 添加或修改（写注册表值、设服务启动方式、集成驱动/更新、放文件入镜像）

```csharp
record ExecSpec { string Resource; Ensure Ensure; JsonObject Desired; }   // 绑定 args 后的纯数据
enum Ensure { Present, Absent }
enum ChangeKind { Created, Modified, Removed, Skipped }

interface IExecuter {
    string Resource { get; }                                               // 如 "registry.service"
    Task<ResourceDiff> InspectAsync(ExecContext ctx, ExecSpec spec, CancellationToken ct);
        // 读当前状态 → Satisfied + Differences（将产生的增/改/删清单）
    Task<ExecResult> ApplyAsync(ExecContext ctx, ExecSpec spec, CancellationToken ct);
        // 内部先 Inspect：已满足→Skipped（幂等）；否则收敛执行，返回 Changes[] 变更清单
}
// ExecResult { Status(Applied/Skipped/Failed), Changes: ChangeItem{Kind, Target, Before, After}, SkipReason, HResult }
// ExecContext { MountPath, LayerIndex, Logger, BuildId, FastMode ... }
```

初始资源集合（v1 对等能力 + 统一化 + 预留扩展）：

| Resource | 能力（present / absent） | 对应 v1 handler |
|---|---|---|
| `registry.value` | present=增/改值（离线 hive，类型映射 DWord/QWord/String/Expand/Multi）；absent=删值 | Registry.SetOfflineValue |
| `registry.service` | present=设定服务启动 auto/delayedAuto/manual/disabled（含 Select\Current 控制集解析、通配服务名）——**统一 v1 的 Disable/Configure 两个分裂 handler** | Registry.DisableOfflineService + ConfigureOfflineService |
| `dism.feature` | absent=移除可选功能（removePayload）；present 预留给启用 | Dism.RemoveOptionalComponent(feature 分支) |
| `dism.capability` | absent=移除能力 | Dism.RemoveOptionalComponent(capability 分支) |
| `dism.package` | absent=按 pattern 移除 CBS 包 | Dism.RemovePackage |
| `dism.component-store` | 维护型资源：StartComponentCleanup / ResetBase | Dism.ComponentCleanup |
| `appx.provisioned` | absent=按通配移除预装应用 | Appx.RemoveProvisioned |
| `driver.store` | absent=按 INF 白名单移除内置驱动（FileRepository 路径约束） | DriverStore.RemoveInbox |
| `fs.path` | absent=删镜像内路径（防穿越）；**present=从 plan assets 目录复制文件/目录入镜像（新增能力）** | Filesystem.RemovePath |
| 预留：`dism.driver` / `dism.update` / `image.unattend` | 集成驱动 / 集成更新 / 注入 unattend——**接口与注册机制就绪，数据格式不破坏兼容，后续版本实现**（v1 research doc 已规划） | — |

要点：
- 每个资源带 JSON Schema（Desired 校验 + 未来 GUI 自动渲染参数编辑器）
- **幂等免费获得**：Apply 先 Inspect，已满足→Skipped；v1 的"目标缺失即跳过并记录"语义自然继承
- **语义级变更日志**：每个 exec 返回 Changes[]（Created/Modified/Removed + before/after），逐层汇入 LayerRecord——与 §4 的文件级 layer diff 互补：回溯时既知道"声明意图改了什么"，也知道"磁盘上实际动了什么"
- Inspect 支撑 `tinywin2 preview`：在基础层上跑全量 Inspect 生成影响预览报告（v1 research 中的 Inspection 阶段），M4 交付
- 错误分类用 HRESULT/退出码常量（CBS_E_INVALID_INSTALL_STATE=-2146498541 等，dism 4350 特例），替换 v1 的中英文本地化正则
- `RegHiveSession`：hive load/unload 带重试；`ExecuterRegistry` 是唯一分发点（等价 v1 allowlist 但强类型）

## 3. Plan 模型：组合 + arg + 分组（需求 2/5/7）

v2 plan JSON（schemaVersion 2）：

```json
{
  "schemaVersion": 2, "id": "service.workstation", "version": "2.0.0",
  "title": "Workstation 文件共享客户端", "group": "Networking",
  "tier": "Standard", "conflicts": [], "requires": [],
  "arguments": [
    { "name": "startMode", "type": "enum", "label": "启动方式", "default": "delayed",
      "options": [
        { "value": "delayed",  "label": "延迟启动", "risk": "Medium" },
        { "value": "manual",   "label": "手动",     "risk": "Low" },
        { "value": "disabled", "label": "禁用",     "risk": "High" }
      ] }
  ],
  "execs": [
    { "resource": "registry.service", "ensure": "present",
      "with": { "services": ["LanmanWorkstation"],
                "start": { "$map": { "arg": "startMode",
                  "cases": { "delayed": "delayedAuto", "manual": "manual", "disabled": "disabled" } } } } }
  ]
}
```

- **组合（需求 2）**：`PlanDefinition`（叶子：execs 列表）与 `PlanGroup`（组合：有序子 plan）；构建 = 顶层 plan 的顺序序列；依赖递归解析 + 冲突拒绝 + 环检测（移植 v1 `New-TinyWinBuildPlan` 算法）
- **arg（需求 7）**：`arguments` 声明类型/默认值/选项（enum/int/bool/string）；exec 的 `with` 通过 `$arg` 引用与 `$map` 变换绑定；**解析期完成绑定与校验**，产出的 ExecSpec 是纯数据
- **分组（需求 5）**：`group` 字段映射 v1 category；GUI 默认把同组折叠为一个组合 plan（也是默认分层单位），可切换"每条 plan 单独一层"

## 4. VHDX 差分链分层 + plan 间原子性（需求 3）

- `DiskPartVhdBackend : ILayerBackend`：diskpart 脚本实现差分盘创建（parent=）、attach/detach、merge；盘符用 attach 前后逻辑驱动器快照差分解析（零依赖）
- `VhdLayerStack`：`base.vhdx` + `L001…Ln.vhdx` 差分链 + 每层 `LayerRecord`（planId、绑定后 args、**各 exec 的 Changes 汇总**、时长、状态、父层指针）→ 持久化 `layers.json`

```
1. 源解析：ISO 挂载(Mount-DiskImage)/目录校验 sources\install.{wim,esd}
2. ESD 源先 Export 成临时 WIM（v1 逻辑）
3. 基础层：可扩展 VHDX(127GB 精简配置)→分区/格式化/盘符→ dism /Apply-Image 选中索引 → base.vhdx
4. 逐顶层 plan：
     diff = CreateDiffLayer(parent=当前叶子) → attach → 盘符
     foreach exec: executer.ApplyAsync(...)      # 任一硬失败即抛
     dism /CheckHealth 快速健全性检查（Fast 模式跳过）
     detach → 层 Commit（保留 VHDX + LayerRecord）
   异常：强制 detach → 删除该 diff VHDX → **镜像状态与该 plan 执行前完全一致（原子性）**
   策略：默认中止并保留全部层供取证；--continue-on-error 可跳过继续
5. 链深保护：>30 层自动 diskpart merge 合并最旧 K 层（清单记录合并范围）
```

**回溯工具链**（CLI `layer` 命令，GUI 结果页一键复制）：
- `layer list`——链条 + 每层 plan/参数/状态/大小/耗时/语义变更摘要
- `layer diff N-1 N`——分别只读挂载两层：文件树 diff（尺寸/属性初筛→差异项哈希）+ 五大 hive `reg.exe export` 解析对比 → "该层删/改了哪些文件与注册表值"
- `layer rollback-to N`——直接从第 N 层捕获输出（天然丢弃后续层）
- `layer extract`——从指定层提取单个文件
- 失败构建默认**保留层文件**；成功后 `--keep-layers` 控制

## 5. 输出（需求 4）

- 叶子层挂载 → `dism /Capture-Image` → `install.wim`（LZX fast/max）或 `install.esd`（recovery/LZMS）；名称/描述/FLAGS 取自 `/Get-WimInfo` 源索引元数据
- 媒体重建：robocopy 源媒体 → `out/TinyWin2-<buildId>/`，替换 `sources\install.*`
- 可引导 ISO：oscdimg 双 BIOS+UEFI（精确移植 v1 参数：etfsboot.com + efisys.bin/noprompt，`-m -o -u2 -udfver102`）
- `--out-vhdx`：链 merge 成单文件 VHDX，可直接挂 Hyper-V 冒烟启动
- `tinywin2-manifest.json`：构建信息 + 层清单（plan/args/Changes）+ 最终镜像 SHA256

## 8. GUI：WinUI 3 四页向导（需求 6）

- **非打包（unpackaged）+ 自包含 + app.manifest requireAdministrator**（解决 v1 MSIX 无法提权的问题；启动检测并提示）
- GUI 一律 spawn `TinyWin2.Cli build --json-events`（重定向 stdout），CLI/GUI 行为完全一致；移植 v1 的 OscdimgLocator/镜像探测/日志流
- **页 1 源与输出**：选 ISO/文件夹 → 后台 `inspect` 列索引 → 选索引 → 输出模式（WIM/ESD/可引导 ISO/ISO+VHDX）+ 压缩档 + 分层粒度；oscdimg 自动探测
- **页 2 精简项目**：按大类折叠树（搜索、tier 筛选、组级全选）；plan 行内 **arg 编辑器**（enum→ComboBox 含各选项风险、bool→Toggle、int→NumberBox）；Profile 导入/导出
- **页 3 进度日志**：加权总进度（媒体复制→基础层→逐层→捕获→封装）、每层状态徽章、彩色实时日志流、取消（杀进程树）
- **页 4 结果**：成功→产物清单（路径/大小/哈希）+ 层报告 + 打开文件夹；失败→失败 plan/层、错误详情、下一步建议（layer diff 命令、排除该 plan 重试）、复制诊断信息
- 构建前可返回修改，构建开始后锁定导航

## 9. v1 迁移（tools/migrate-v1）

- 解析 `..\tinywin\entries\*.json` → `plans/*.json`；id 重映射（`registry.disable-workstation-service`→`service.workstation`）
- **handler → resource 映射**按 §2 表；**参数对合并**：同 resource + 同目标（services/features/patterns 一致）但 mode 不同的条目组 → 合并为单一带 enum arg 的 plan，选项风险取自原条目；输出 old→new 映射表存档
- 迁移器为纯函数核心 + 驱动入口，golden 文件测试保证可复现

## 12. 风险与对策
- **整体比 v1 慢**（Apply 基础层数分钟 + 重新捕获）：`--fast` 缓解；分层归因能力是明确换取的目标
- **dism 对挂载 VHDX 服务**：业界标准做法；doctor/集成测试提前暴露个别 provider 问题
- **链深与磁盘占用**：默认按组分层（10~16 层）+ 30 层自动合并；doctor 预估并检查 ~50GB 可用空间
- **WinUI 非打包提权**：manifest requireAdministrator；若后续回 MSIX 再改"提权子进程 + JSONL 文件尾随"通道
- **Capture 元数据**：捕获镜像用源索引的 Name/Description/FLAGS 补齐；集成测试验证 setup 可选版识别
